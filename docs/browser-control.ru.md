# Управление прокси в браузере

Откройте **http://127.0.0.1:8789/**. Эта панель работает в супервизоре и остаётся доступной при зависании обработчика запросов. Codex по-прежнему подключается к `http://127.0.0.1:8788/v1`; менять его конфигурацию не требуется. На общем сервисе панель доступна любому пользователю того же компьютера. Установка и настройка автозапуска описаны в [инструкции Windows](windows-installation.md).

В шапке выберите «Русский» или English. Язык, формат чисел и дат сохраняются в этом браузере. Настройки самого прокси общие для его пользователей.

Установочные скрипты также задают `gpt-6.1-sol` для извлечения и объединения памяти Codex, если эти модели ещё не указаны явно. Это помогает избежать вызовов Terra, когда для неё нет канала у провайдера. Основная модель и остальные настройки сохраняются; отключённая память не включается. Перед изменением создаётся приватная резервная копия конфига.

Для уже установленного прокси запустите из папки репозитория `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\configure-codex-memory.ps1`, затем выполните **Developer: Reload Window** в VS Code или перезапустите Codex. Если Terra уже прописана явно, добавьте `-OverwriteMemoryModels`. На общем ПК запустите помощник в сеансе каждого пользователя Codex. Настройка памяти выполняется при установке; обновление из браузера её не запускает. Параметры модели, пути к конфигу и пропуска настройки описаны в [инструкции](windows-installation.md#codex-memory-models).

| Раздел | Что можно сделать |
| --- | --- |
| Обзор | Посмотреть активные ответы и очереди, поставить новые запросы на паузу, возобновить работу или перезапустить прокси. |
| История | Посмотреть время, длительность, статус и объём запросов; отфильтровать ошибки; открыть графики RAM и очередей, события восстановления и автоматические отчёты. |
| Диагностика | Включить временное измерение, остановить его и скачать JSON с показателями. |
| Настройки | Изменить сжатие, таймауты, повторы ошибок, квоты и буферы стрима. |
| Обновления | Проверить main форка, подготовить пакет и подтвердить установку. |

Настройки сохраняются для всего экземпляра прокси отдельно от `.env`. Нажмите «Сохранить», затем «Применить перезапуском». Изменения применятся к новому процессу. Если другая вкладка уже сохранила настройки, панель попросит обновить значения.

Обычный перезапуск ждёт завершения активных ответов и временно останавливает новые запросы. Панель переподключится сама. Флажок «Перезапустить сразу» прервёт активные ответы: используйте его, если ожидание завершения неприемлемо. Ожидающий перезапуск можно отменить до начала перезапуска процесса.

Для обновления нажмите «Проверить обновления», затем «Подготовить обновление». Проверяются четыре успешные CI-задачи выбранного коммита, состав пакета, зависимости, загрузчик восстановления и запуск без ключей. Подготовка не останавливает рабочий прокси. Установка требует отдельного подтверждения, сохраняет предыдущие файлы и проверяет новый процесс. При ошибке запуска выполняется откат; результат появится после переподключения панели.

С версии 1.9.2 проверка и подготовка запускаются в фоне: можно перейти в другой раздел, обновить страницу или закрыть вкладку. Результат остаётся доступен, пока работает этот экземпляр прокси. Независимая панель обновляет состояние примерно раз в две секунды. Повторное нажатие присоединяется к той же задаче; перезапуск и установка недоступны до завершения подготовки. Если подготовка не удалась, нажмите «Повторить подготовку». Браузер больше не ждёт завершения всей операции в одном HTTP-запросе.

Для общей установки браузерные обновления включаются администратором один раз через `enable-browser-updates.ps1` после установки полного runtime и защиты прав доступа. Обновление зависимостей, загрузчика восстановления или добавление новых файлов потребует установки администратором. Ключи, модель и история Codex управляются в самом Codex.

История сохраняется на диске и переживает перезапуск: по умолчанию 2000 запросов за 24 часа, 1440 точек показателей и до 16 автоматических отчётов. В ней нет текстов запросов, ответов, заголовков и ключей. При сбое незавершённый вызов помечается как прерванный после смены рабочего процесса. Время запроса включает весь стрим; ожидание квоты, соединения и подготовка показываются отдельно. Очистка требует подтверждения и не удаляет историю Codex.

После трёх итоговых ошибок за минуту автоматически включается минутный профиль и сохраняется отчёт. Повторный автоматический запуск возможен через пять минут. Пауза и отмена запроса пользователем не считаются причиной для такого отчёта.

Панель и её шрифты работают локально. GitHub проверяется по нажатию кнопки. Интервалы профиля могут перекрываться; их нельзя складывать в общее время ответа модели. Показатель RAM относится к рабочему процессу; супервизор и браузер используют дополнительную память.

При зависании на 8789 появится «Восстановить прокси». Кнопка с подтверждением заменяет рабочий процесс, сохраняя панель, настройки и историю. По умолчанию супервизор также восстанавливает его автоматически после трёх неудачных проверок с интервалом 10 секунд. Первые 30 секунд после запуска дают на инициализацию; ограничение — три автоматических восстановления за 10 минут. Долгий ответ провайдера сам по себе не вызывает перезапуск, если обработчик отвечает на проверки.

Независимая панель требует запуска через `service.py` или `machine_service.py`. При прямом запуске `proxy.py` доступна только панель на 8788. Если порт 8789 занят, задайте свободный `PROXY_PANEL_PORT` в `.env` и перезапустите сервис. При невозможности запустить независимую панель автоматическое восстановление не включается; состояние отмечается в логе сервиса.

Если супервизор полностью остановлен и обе панели недоступны, нужен запуск его задачи Windows. Для общего сервиса: в PowerShell администратора выполните `Start-ScheduledTask -TaskName AgentRouterCodexProxyMachine`, затем откройте панель снова. Перезагрузка ПК обычно не требуется.
